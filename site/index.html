OpsClaw

A self-hosted SRE agent that watches your infrastructure, diagnoses faults, and acts only within the autonomy you grant — with every command risk-classified, gated, and written to a hash-chained audit log.

What it is

One team runs one daemon: a single Rust binary that owns the heartbeat loop, the incident lifecycle, the approval queue, a shared team memory, and the audit chain. Your team reaches it through the web UI it serves (an installable PWA with push to your lock screen), Telegram, or the CLI. It is an installed product — your infrastructure credentials live on your host, and there is deliberately no hosted console that can reach into your deployment.

Autonomy is a dial, not a promise

levelwhat the agent may do
observeRead-only. Every mutation it would have run is written to a dry-run log instead — you see what it would do before letting it.
suggestMutations queue as approval requests — full context, decidable from a phone. The default.
act_on_knownExecutes on its own only when a runbook you wrote matches — human knowledge as the boundary of automation.
autoExecutes routine and moderate-risk commands autonomously.

Destructive commands never auto-execute at any level, and a hard-block list is refused always. Autonomy resolves per target — prod can sit at suggest while staging runs auto.

Built so you can trust the log

One choke point

Every remote command — ssh, kubectl, an ArgoCD rollback — passes through a single policy gate. No code path reaches an executor around it.

Risk classified in code

Pattern-based classification decides what a command is. The model never decides its own permissions.

Hash-chained audit

Append-only, sealed on both sides of execution, verifiable with opsclaw audit verify. Secrets are scrubbed before anything is persisted.

E-stop that works

A sentinel file the CLI writes directly — no daemon round-trip — halts everything, even a wedged daemon.

Approvals run verbatim

Approving executes the stored command exactly — never a fresh interpretation of “yes, do it”.

Dead-man heartbeat

An internal watchdog catches a stalled loop; an external heartbeat pages you when the daemon itself goes silent.

Install

The standard install is a docker-compose file — the daemon plus a pinned memory backend — and a ten-minute onboarding:

opsclaw-cli onboard        # wizard: team, targets, credentials, VAPID keys
opsclaw-cli doctor         # probe every target, verify the wiring
opsclaw                    # run the daemon

Targets in v1: ssh (jump hosts included), local, kubernetes, cloud. Endpoint tools for Elasticsearch, Prometheus, ArgoCD, Azure Service Bus, and EventStore/KurrentDB ship enabled; more sit behind the same trait. Run it adjacent to what it watches — a bastion or ops host — so it can report a dead cluster from outside; an in-cluster Helm chart exists for teams that want it.
